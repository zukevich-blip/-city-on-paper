# City on Paper — протокол экспертных агентов и кураторской приёмки

Дата: 2026-11-03. Статус: **рабочая модель контроля**, а не свидетельство участия реальных людей или автономно запущенных агентов.

## Миссия
Каждая единица каталога должна отвечать: **что это за произведение; откуда оно; что в нём стоит рассмотреть; какую мысль посетитель унесёт; на каких правах мы его показываем**. Количество картинок не служит показателем качества само по себе.

## Роли и передача между ними
| Направление | Вход | Выход и стоп-фактор |
|---|---|---|
| Архивный исследователь | музейные API, каталоги, книги, инвентарные номера | точная ссылка, ID, дата, автор; отсутствие первоисточника = не публиковать как подтверждённое |
| Искусствовед/историк архитектуры | первоисточник и контекст | наблюдаемое отдельно от интерпретации; атрибуция Бенуа без смешения художников |
| Редактор образовательных историй | проверенные объекты | короткий маршрут, вопрос на внимательное рассмотрение, подтверждаемые утверждения |
| Фотоисследователь/географ | исторический вид, современное фото | точка съёмки, ракурс, степень соответствия, без фиктивных «идеальных» совпадений |
| Юрист по правам | объект, изображение, URL и условия | CC0/public domain/CC BY и обязательства, либо только ссылка |
| Дизайнер выставок | изображения, логика, сюжет | выразительная композиция без декора поверх искусства, нормальная мобильная адаптация |
| UX/доступность | сценарий посетителя | навигация с клавиатуры, заголовки, alt, отсутствие ловушек, контраст |
| Инженер | валидированные записи и UI | независимая ветка, тесты, читаемые схемы данных, устойчивое поведение без сети |
| QA/безопасность | runnable bundle и CI | реальные тесты (включая мобильные viewport), логи, проверки источников; запрещён скрытый сбор личных фотографий |
| Маркетинг/аналитика | испытанный продукт, реальные данные | проверяемая гипотеза привлечения, не выдуманные показатели популярности |

Роли могут быть исполнены автоматизированными проверками, авторским кураторским ревью или приглашёнными реальными людьми в будущем. Одна роль **не считается независимой экспертизой**, когда решения принимает один и тот же ассистент. Требуется внешняя проверка для решений, где важны исторические и правовые последствия.

## Реальные автоматизированные проверки
- GitHub Actions: ruff, pytest, целостность каталога, Chromium Playwright, пакет runnable-превью.
- `tests/test_salon.py`: структура каталога CC0 и элементы «Салона».
- `tests/test_exhibition_city_evidence.py`: 9 ссылок на произведения из каталога, права и источники.
- `tests/browser/qa_salon_exhibition.js`: три viewport, фильтр по художнику, избранное, световой просмотр, три маршрута, сравнение и ссылки с главной.
- **Остаётся сделать вручную**: Safari на реальном iPad/iPhone, историческое редактирование девяти объяснений, оценку визуальной композиции и исключение фактических искажений.

## Кураторский формат — пять обязательных полей
1. **Оригинал**: музей, номер, канонический URL, точное название и авторство, источник даты.
2. **Права изображения**: статус и ссылка на политику, дата проверки, ограничения на локальное хранение.
3. **Визуальная ценность**: что видит человек при масштабе/крупном плане и почему.
4. **Образовательный вопрос**: на что предлагается обратить внимание, ответ по самому листу, без искусственной исторической достоверности.
5. **Неопределённость**: что нельзя заключить только по изображению (точность ракурса, дата натуры, изменения здания).

## Контроль качества перед выпуском
- G0. Уникальная история, не дубликат карточки каталога; пользовательский смысл сформулирован.
- G1. Проверка источника и атрибуции, перепроверка Бенуа и подписей.
- G2. Изображение показано в достаточном разрешении, формат/размер не искажён.
- G3. Лицензионные условия соблюдены; личный характер использования не интерпретируется как разрешение распространять любые файлы.
- G4. Accessibility и UX (в т.ч. reduced motion, клавиатура, читаемость).
- G5. Автотесты, ручной Safari и тест при медленной сети.
- G6. Публичный релиз только после приемки целой цепочки draft PR и финального архивного бандла.

## Итог работы этого этапа
1. «Салон» на 41 произведение, без необходимости скачивать файлы из музейного CDN.
2. «Город как свидетельство»: Рим, Венеция, Париж, по три музейных работы и последующее сравнение двух листов в каждом маршруте.
3. Главная страница с двумя новыми переходами.
4. Исторический контент представляет собой вопросы и анализ визуальной композиции, не утверждения о фактическом состоянии города в конкретный день.
5. Ни одна новая функция не объявляется опубликованной, пока не пройдены CI и ручная приёмка.

## Следующий набор задач, по порядку
1. Зелёный CI, пакет содержит новые пути и JSON, браузерный QA.
2. Редакторское/искусствоведческое ревью девяти карточек.
3. Углублённый zoom на OpenSeadragon с BSD-notice, без локального дублирования тяжёлых оригиналов.
4. Десять корректных пар исторического/современного города с географической проверкой.
5. Увеличение каталога через Cleveland + IIIF/BnF/LoC/Met, только с паспортами источника и прав; число записей не должно скрывать качество.
6. Три измеряемых пользовательских сценария; затем объективная проверка интереса посетителей.
