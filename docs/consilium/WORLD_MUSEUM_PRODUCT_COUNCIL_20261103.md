# City on Paper — международный консилиум: практики, лицензии, продукт (03.11.2026)

## Назначение
Развивать самостоятельный визуальный музей истории городов, архитектурной графики, литографий Бенуа, тематических альбомов, фото и художественных ремёсел. Приоритет — удовольствие от открытия подлинных объектов, культурная достоверность, высокое качество просмотра, повторное посещение.

## Экспертные направления консилиума
Это функциональные экспертные роли при оценке решений, **не утверждение об участии реальных приглашённых специалистов**:
1. Куратор и историк графики: авторство, датировка, различение Феликса, Филиппа и иных Бенуа.
2. Библиотекарь и специалист IIIF: оригиналы, каталожные идентификаторы, изображения, метаданные.
3. Специалист интеллектуальной собственности: права работы / цифрового файла / фотографии / интерфейсного кода отдельно.
4. Искусствовед архитектуры: топонимы, изменения и исчезнувшие памятники.
5. Географ и фотограмметрист: точность исторического/современного ракурса, степень наложения.
6. Редактор, сценарист и преподаватель: интерактивное расследование без фактических выдумок.
7. Арт-директор: композиция с уважением к листу, типографика, контрастность.
8. UX-исследователь: быстрый вход, навигация, доступность, комфорт планшета.
9. Frontend-инженер: доступный адаптивный сайт, PWA, производительность.
10. Backend/данные: индекс, поисковый API, IIIF, кэш, CDN и происхождение данных.
11. Security/privacy: политика загрузки пользовательских фото, защита API.
12. Маркетолог/аналитик: воронка, канал и измерение, реальные показатели после релиза.
13. QA: regression, Safari/iPad, сетевые ошибки, атрибуция, лицензии.
14. Архитектор развёртывания: статический хостинг сначала, управляемые сервисы по мере необходимости.
15. Специалист по инклюзивности: WCAG и предпочтение reduced motion.

## Принятые продуктовые решения
**Веб-платформа и PWA в первую очередь.** Не начинаем параллельный native iOS/Android: сайт доступен с телефона, планшета и компьютера, индексируется поиском и легче обновляется. PWA и офлайн добавлять после проверки реальной сборки и прав на кэширование.

**Хранение**: GitHub — исходный код, метаданные, тесты, небольшие превью при наличии прав. IIIF-оригиналы — по разрешённым ссылкам музеев. При росте — объектное хранилище/CDN с контролем прав, а не бинарные гигабайты в Git.

**Порядок навигации**: «Салон» → «Города и эпохи» → «Тогда / Сейчас» → «Детектив» → «Ателье» → «Коллекция». На главной выделить три коротких входа: случайная работа, 90-секундное расследование, сравнение старого/нового вида.

## Реально добавлено в этой ветке
- `salon/index.html` — статический интерфейс, который читает существующий проверенный `data/curation/cc0-gallery-20261103.json` (41 запись).
- Поиск имени, автора, города; город и век; случайная работа; крупный просмотр; ссылка на музей; избранное в localStorage.
- Отсутствует сторонний трекер и загрузка пользовательских фото на сервер; фавориты остаются в браузере.
- Никаких дополнительных художественных файлов в Git не скачано. Изображения открываются с адресов музея.

## Лицензии и копирование лучших практик
- Открытый исходный код использовать только в границах лицензии конкретного репозитория, с required notices, лицензией и проверкой транзитивных зависимостей.
- Copyleft (например, GPL/AGPL) требует отдельного анализа, прежде чем включать код в продукт.
- CC0 музейных изображений не делает автоматически CC0 фотографии, бренд, описание и сайт музея.
- Закрытые интерфейсы: изучать публично видимые паттерны, реализовывать своё решение с оригинальным кодом и визуальным языком; запрещённое обходом ограничений копирование исключено.
- AI-подписи, «автовосстановление», фотографии, отсутствующие в источнике, всегда явно отмечать как реконструкцию, а не архивный оригинал.

## Приоритеты по ожидаемой полезности (гипотезы; без выдуманного пользовательского спроса)
1. Высокодетальный просмотр / динамический каталог — высокий эффект, средний риск.
2. Тогда/сейчас с оценкой точности — сильнейшее отличие, высокий риск ошибочного ракурса.
3. Поиск по географии и эпохе — долгосрочная ценность, средний объём индексирования.
4. Три тематические мини-выставки с настоящей историей — маркетинговый пилот.
5. Публичная загрузка своих фото — позже из-за приватности, модерации, согласий.

## Release gates
- Все открытые PR на данный момент draft и зависят от других draft веток; **не сливать напрямую в main**.
- Проверить все ссылки источников; негативные случаи (404/CORS/долгая загрузка), подписи и CC0.
- `pytest`, браузерные QA, Lighthouse, Playwright/Safari; ручной тест на реальном iPad.
- Проверить теги, контраст, клавиатуру, мобильный viewport, фавориты, корректный fallback.
- Согласовать реальный preview URL; главное — не путать «собрано в PR» с «опубликовано».
- Только после приёмки завести независимую стабильную ветку релиза и настраивать хостинг.

## Следующие измерения после запуска
Уникальные посетители, открытие детальной работы, завершение 90-секундной истории, использование сравнения, создание подборки, возвращение через 7 дней. Собирать только с прозрачным согласием и минимизацией персональных данных, отдельно соблюдать юрисдикционные требования.
