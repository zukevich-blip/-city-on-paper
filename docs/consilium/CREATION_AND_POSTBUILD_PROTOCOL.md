# CITY ON PAPER — КОНСИЛИУМ И КОНТРОЛЬ КАЧЕСТВА НА ВСЁМ ЦИКЛЕ

Дата 9 ноября 2026. Черновая ветка PR #50 поверх PR #48. Этот документ задаёт **проверочные роли и методы**, не выдаёт ИИ за реальных привлечённых специалистов.

## 1. Две независимые группы проверки

**При создании:** художественный руководитель (историческая цельность), экспозиционный дизайнер (ритм и иерархия), типограф/редактор, UX-дизайнер, специалист по мобильному Safari, арт-реставратор цифровых копий (не изменять подлинные сканы), картограф/геодезист, разработчик фронтенда и редактор метаданных.

**После сборки:** независимые роли «скептический проверяющий», QA-инженер, accessibility/WCAG, security/privacy, архивист и искусствовед, GIS-ревьюер, проверяющий производительность на слабом смартфоне. Для итоговой научной приёмки подписываются **люди**; модель не может сертифицировать собственный GCP-подбор.

### Доказательная матрица

| Кто проверяет | Какое условие | Инструмент/доказательство |
|---|---|---|
| Искусствовед и архивист | Художник, техника, век, источник и условия лицензии подтверждены отдельно; «no known restrictions» не CC0 | музейная карточка и её URL, IIIF manifest/Canvas, исследовательское досье |
| Репродукционный специалист | Литография на сайте без CSS desaturation, `filter` и `cover` обрезки; любое увеличение сохраняет геометрию | исходные размеры, браузерный снимок, CSS инспекция |
| Геодезист / GIS | Плоский план не путается с перспективным видом; GCP с независимыми holdouts, осмысленным RMS, маской и указанием вида современной карты | отчёт affine/LOO/holdout, архивная карта, современные открытые ортофото |
| Арт-директор | Гармоничная типографика, цвета и умеренные переходы без декоративной перегрузки | реальные скриншоты 390 / 820 / 1440, дизайн-токены |
| UX / дизайн экспозиции | Маршрут мир → страна → город → планы → произведение → сравнение → оригинал работает с двух направлений | Playwright click-through; `eras/journey.js` |
| Accessibility | WCAG 2.2 A/AA, focus, управление без drag, читаемый масштаб, VoiceOver | axe-core JSON/MD плюс ручной iOS Safari |
| Frontend & PWA | В офлайне JS и JSON не превращаются в HTML; кэши не стирают данные других приложений; экономия памяти | Playwright offline SW и собственные Python-тесты |
| QA и DevOps | Исходники, полная упаковка музея, ссылки, источники, приложения и мобильноe отображение воспроизводимы | GitHub Actions, ruff, pytest, Playwright, `validate_bundle.py` |

## 2. Сначала идея и источник (pre-build)

1. Задача/карточка: что посетитель должен понять и какой архивный оригинал является основанием. Фотографии должны иметь авторство и права.
2. Проверка научного статуса: `source_candidate`, `source_checked`, `research_fit`, `independently_accepted` **разные состояния**. Никакого синтетического GCP, искажённых дат или подставных «заверено».
3. UI: карта и каталог имеют реальное место в общем маршруте, размер/контраст проверяются заранее, а не после оформления.
4. Согласовать нагрузку: источники с API-лимитами не сканируются каждым коммитом; данные для разработки берутся из сохранённых проверенных артефактов.

## 3. При изменении кода (during-build)

- GitHub PR, **без auto-merge, без переключения публичного сайта**.
- В CI проверять `ruff`, `pytest`, реальные изображения и связи документов. Не удалять существующие залы и маршруты ради упрощения шапки.
- `tests/browser/qa_eras.js`: 390/820/1440, переключение карт, ссылки, оригинальные пропорции, пять шагов исследования, отсутствие горизонтального переполнения.
- `tests/browser/qa_eras_offline.js`: реальный offline fetch под контролем service worker, кодовые и JSON-файлы остаются кодом и JSON, отсутствующий файл получает честный HTTP 404 от сервера или HTTP 503 при сетевом сбое, но никогда HTML вместо JS/JSON.
- `tests/browser/qa_museum_a11y.js`: 5 экранов × 3 размера, WCAG 2.2 A/AA + лучшие практики axe-core; отчёт с конкретными CSS селекторами и тяжестью ошибок.
- **Ограничение**: даже ноль найденных проблем в axe-core не означает отсутствие всех нарушений WCAG; нужен ручной тест.
- Не создавать дополнительную тяжёлую страницу, генеративную копию литографии или новый UI-фреймворк без явной цели.

## 4. После сборки (post-build)

1. Собрать **полный музей**, а не только исходную папку. Проверить `tools/release/validate_bundle.py`, затем `tests/browser/qa_packaged.js`.
2. Просмотреть реальные изображения home, world, atlas, Paris, Venice для смартфона/планшета/компьютера. Сохранять док-скриншоты как GitHub Actions artifacts.
3. Разобрать JSON `axe-consilium-audit.json`. Каждую серьёзную/критическую ошибку исправить или явно перенести в список блокеров с основанием; не выдавать автоматический PASS за «доступность подтверждена».
4. Проверить на физическом iPhone Safari и VoiceOver. Пока этого нет, писать `NOT TESTED`, а не `100% Safari`.
5. Проверить на свежем настоящем архивном URL дату, права и авторство перед опубликованием изображений. Картографический GCP требует отдельной независимой проверки.
6. Только после согласования публикации: мониторить доступность URL, broken-image и ошибки Pages, сравнить свежие результаты с последней принятой сборкой; при регрессии откатить.

## 5. Подключённые и допустимые инструменты

**Постоянный инженерный контур:** GitHub PR/Actions, Python + pytest + ruff, Playwright, axe-core, Leaflet, открытые IIIF-ресурсы, архивные API с явными ограничениями. Для художественного и макетного исследования доступны Canva/Figma/Adobe при необходимости согласовать альтернативный дизайн, но **редактировать сам музейный скан средствами генерации, отбеливания или дорисовки нельзя**. Сначала исходник и лицензия, затем оформление вокруг работы. Canva/Figma не обязательны для каждого коммита, чтобы не создавать копии макетов и путаницу версий.

## 6. Итоговые условия ГОТОВО / НЕ ГОТОВО

**Технически ГОТОВО** только когда sources / browser / packaged / offline QA прошли, нет серьёзной открытой регрессии и реальные скриншоты просмотрены.

**Научно ГОТОВО** только после независимой приёмки атрибуций, прав и используемых GCP. Отдельно считать 2447 географических кандидатов, архивные карты, привязанные планы и опубликованные работы.

**Публично ГОТОВО** только после явного решения владельца о выпуске, проверки условий хостинга/доступа и реального iOS Safari. Нельзя подменять это зелёными тестами Chromium.
