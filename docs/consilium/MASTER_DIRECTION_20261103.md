## 3. Технологические варианты и решение

| Продукт / библиотека | Что брать | Решение | Почему |
|---|---|---|---|
| OpenSeadragon v6.1.1 · https://github.com/openseadragon/openseadragon | tile-based deep zoom, IIIF, доступное колесо/жесты | **Пилот**, без добавления CDN в основной сайт до верификации `info.json` | Большие альбомные листы потребуют 4K–20K детализации, собственные сканы 1024 px недостаточны |
| IIIF Presentation 3 · https://iiif.io/api/presentation/3.0/ и Cookbook https://iiif.io/api/cookbook/ | Манифесты альбомов, постраничная структура, граф аннотаций | **Базовый стандарт данных** для следующего модуля | Вендор-независимая модель музейных страниц и точек, документированный интерфейс |
| Mirador · https://github.com/ProjectMirador/mirador | научное сравнение нескольких IIIF изображений и аннотаций | **Отдельный читальный зал**, позже | Не грузить тяжёлый viewer на каждый телефонный экран |
| Diva.js · https://github.com/DDMAL/diva.js | лёгкая навигация по страницам исторических книг | Сравнить в прототипе с Mirador | Проверить права и реальную доступность полного альбома |
| Knight Lab JuxtaposeJS · https://github.com/NUKnightLab/juxtapose | знакомое управление до/после | **Не встраивать как есть**; интерфейс уже есть свой | В README прямо оговорено, что кредит может быть HTML, что создаёт XSS-риск для внешних данных; нельзя обещать точное выравнивание |
| Leaflet · https://leafletjs.com | карта подтверждённых объектов / фототочек | Следующий этап, только при подтверждённых координатах | Карта без достоверной точки вводит в заблуждение |
| Omeka S + IIIF module · https://omeka.org/s/docs/user-manual/modules/iiifpresentation/ | музейная CMS, item sets и манефесты | Изучить только при резком росте редакционной команды | Сейчас добавление хостинга/БД повысит стоимость, не решая главную проблему проверки атрибуции |
| Getty Linked Open Data · https://data.getty.edu/ | модель provenance / linked art | Использовать как справочную архитектуру | Нужна связь объектов, людей, организаций и документов, а не общий список картинок |
| Playwright · https://playwright.dev | сквозной UX на iPhone/iPad/desktop | **Оставить обязательным** | Без живого браузерного QA на каждом PR интерактивные разделы будут ломаться |
| GitHub Actions / source checks | QA, сборка переносимого архива, откат | **Главный единый контур** | Без merge safety нельзя безопасно заменить старый опубликованный сайт |

Библиотеки **изучены/сопоставлены**, но сторонние репозитории целиком не клонировались, и недокументированные подключения не выдаются за работающие. Отсутствуют основания устанавливать все сразу.

## 4. Принятое решение: из галереи в интерактивную исследовательскую энциклопедию

**Главная сущность — проверенное произведение с доказательствами.** Рядом: люди и роли, архитектура, город и эпоха, техника печати, источник цифровой копии, сведения о заказе (или статус «не найдено»), современная фотография/ракурс и пользовательские заметки.

**Главная фишка — «Литография под лупой» + «Кабинет коллекционера».** Первый даёт исследовательскую историю, второй сохраняет результаты изучения, источники и вопросы, которые ещё предстоит выяснить. Практическая польза: готовый личный архив для коллекционирования, учёбы, поездок и небольших исследований.
