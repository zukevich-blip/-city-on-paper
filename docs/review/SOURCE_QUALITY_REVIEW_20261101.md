## 2. Проблемы качества, которые нельзя скрывать итоговой цифрой 333

| Проверка | Результат | Решение |
|---|---|---|
| Уникальные provider:id | 333 / 333 | Дубликатов идентификатора нет; изображения одного оригинала в разных музеях ещё могут повторяться |
| Права `open` | 119 | **Кандидаты**, не разрешение на автоматическую публикацию |
| Права `restricted` | 165 | Только карточка со ссылкой, никаких изображений без отдельной лицензии |
| Права `unknown` | 49 | Проверить предметную карточку источника; для LoC выдача поиска недостаточна |
| `source_url` отсутствует | 1, `smithsonian:ld1-1643399055209-1643399065053-1` | Исправить стабильную ссылку до публикации |
| `food_market` по ключам | 47 | Это **подсказка**, а не 47 проверенных рыночных сцен; есть ложные случаи |
| 45 учреждений | 45 по метаданным; **9 прямых поисковых коннекторов** | Europeana агрегирует многие учреждения, что нельзя приравнивать к независимому техническому доступу к 45 API |
| Подтверждённые пары «тогда/сейчас» | 0 | Не подменять статус кандидатами |

Из тематических ложных или спорных результатов требуется ручной просмотр как минимум:
- `loc:2021670358`, `loc:2021670189`, `loc:2021670214`, `loc:2021670197`, `loc:93512408`: **Market Street**, название улицы, не рыночный сюжет.
- `loc:2002718729`, `artic:97908`: **slave market**, не гастрономия; сохранять в общем историческом каталоге только с корректным контекстом, не автоматически включать в кухню.
- `artic:62042`: натюрморт с рынком в названии, но не городской вид.
- `artic:896`: «Road to Market», требует проверки по изображению.

Не нужно массово удалять такие предметы из общей истории искусства: лучше выводить их из **гастрономической городской подборки** после кураторского решения.

## 2.1. Безопасный показ изображений при неизвестных правах

**Исправлена fail-closed политика**: поле `preview_url` теперь сохраняется только при предварительной категории `open`. До исправления в 49 карточках с `unknown` могли оставаться адреса превью, несмотря на отсутствие проверки прав. **48 превью** удалены из машинного снимка; источники и метаданные записей сохранены. Это ограничение для автоматического интерфейса, а не запрет куратору позже проверить и вручную разрешить конкретную цифровую копию. Добавлен тест неизвестной лицензии.

## 3. Следующие высокоценные подключения

**A. Paris Musées / Musée Carnavalet — высокий приоритет.** Официальное GraphQL API для собраний парижских музеев, включая рисунки, эстампы и виды улиц. Требует бесплатной регистрации и `auth-token`; заявлен лимит 1 000 запросов в день. Не тестировали в авторизованном режиме; **НЕ** считать действующим коннектором.
- Информация: https://www.parismuseescollections.paris.fr/fr/documentation-de-l-api-du-portail-des-collections
- Настройка: https://apicollections.parismusees.paris.fr/
- Условия: https://parismuseescollections.paris.fr/en/node/777951
- Использовать GraphQL только с токеном и подтверждением прав на конкретные цифровые изображения.

**B. INHA AGORHA — высокий приоритет для идентификации художников и издателей.** Данные профессионального французского института истории искусства, особенно полезны для омонимов Benoist, литографов Lemercier/Cicéri и связей с альбомами. Публичная карточка проверена; формальный API ещё не проверен, поэтому на первом этапе — `source_url` и ручная сверка, без обещания коннектора.
- https://agorha.inha.fr/

**C. Europeana — ключевой европейский агрегатор.** Демо-ключ подходит для проб. Для регулярного сбора оформить персональный бесплатный API key и хранить только в environment/secret store.
- https://api.europeana.eu/en

**D. Rijksmuseum IIIF — глубокое увеличение, не новая поисковая база.** Использовать IIIF Presentation и Image API только после поиска Linked Art; лицензию на медиа проверять отдельно.
- https://data.rijksmuseum.nl/tutorials/iiif/

**E. NYPL Collections — исторические меню**, актуальный новый endpoint `/search`, но нужен согласованный токен и проверка прав. Не использовать закрытый `api.repo.nypl.org`.
- https://api-collections.nypl.org/docs
