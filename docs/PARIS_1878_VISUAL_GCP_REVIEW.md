# Париж 1878: визуальная проверка 6 опорных точек

Инструмент `tools/iiif/render_paris_gcp_review.py` создаёт **6 отчётных PNG** (исторический фрагмент / современная позиция / остаточная ошибка), `overview.png` со всеми 15 GCP, `index.html` для просмотра и `review.json` для фиксации результатов.

Важно: это **исследовательская заготовка**, а не подтверждение картографической точности. Остаточная ошибка аффинной модели может быть маленькой даже при неверно выбранном историческом ориентире.

## Запуск с официальным изображением LoC

Нужен Python с Pillow, который уже используется в QA репозитория.

```bash
python -m tools.iiif.render_paris_gcp_review --download-loc --out /tmp/paris-1878-review
```

Команда запрашивает **только один** 25-процентный JPEG через реальный официальный IIIF-сервис карты LoC `2012586603` (никакого массового скачивания). При невозможности доступа используйте уже сохранённую версию ТОГО ЖЕ листа:

```bash
python -m tools.iiif.render_paris_gcp_review \
  --historic-image eras/img/loc-2012586603-paris-1878.jpg \
  --out /tmp/paris-1878-review
```

Пиксельные координаты из `data/vision-lab/georef-paris-1878.json` автоматически масштабируются по размерам конкретной копии изображения. Не подменяйте источник похожей картой другого издателя.

## Добавление спутниковой/современной подложки

Только если имеется **законно полученный**, подписанный, ориентированный севером вверх растр **в Web Mercator (EPSG:3857)** с точными границами в WGS84. Обычный JPEG без известной географической привязки недостаточен; пиксель изображения на современном сервисе нельзя объявить координатой по приблизительной рамке.

```bash
python -m tools.iiif.render_paris_gcp_review \
  --historic-image eras/img/loc-2012586603-paris-1878.jpg \
  --modern-image /path/to/authorized_paris_raster.png \
  --modern-bounds WEST SOUTH EAST NORTH \
  --modern-attribution "Provider / licence / year" \
  --out /tmp/paris-1878-review
```

Значения `WEST SOUTH EAST NORTH` берутся **из метаданных вашего лицензированного растра**, а не угадываются по центру Парижа. Они должны охватывать каждую точку с запасом минимум 400 м. Если снимка нет, в середине и справа показывается **явно подписанная геосхема**, а не поддельный спутниковый вид.

Нельзя использовать `tile.openstreetmap.org` для автоматической пакетной загрузки и создания отчётных карт. Бесплатные OSM-плитки доступны для обычного интерактивного просмотра согласно политике: https://operations.osmfoundation.org/policies/tiles/ . Спутниковые снимки Google/Mapbox применяются только в рамках их лицензий.

## Человек проверяет

Для каждой из шести работ открыть `index.html` и записать отдельно:

1. Правильно ли установлена **сама историческая точка** на оригинале (центр или основание здания, площадь, подходящий перекрёсток)?
2. Правильно ли установлен **современный ориентир** (точка того же элемента, а не центра многоугольника)?
3. Сохранился ли объект, изменился ли его контур или только название, есть ли подтверждающая архивная ссылка?
4. Не выглядит ли геометрическое совпадение ложным из-за допущений аффинной модели и неравномерной плотности GCP?
5. Указать `reviewer`, дату, `pass/fail/needs_more_evidence`, источник каждого исправления, и только тогда предлагать обновление координат.

**Нельзя** утверждать, что все шесть объектов проверены только по графикам и остаточным ошибкам. При необходимости применять Allmaps Georeference Annotation `data/research/paris-1878-georeference-draft.json` через уже существующий экран города; пользовательскую интерфейсную интеграцию делать отдельным PR после фактической визуальной приёмки.

Связанные задачи: #42; исходники и технические ограничения: `docs/IIIF_PILOT_FINDINGS_20261109.md`.

## Исследовательское наложение внутри существующей карты Парижа (draft PR #44)

Слой не публикуется автоматически; в рамках PR добавлены:
- `eras/historical-overlay.js`: Leaflet raster overlay с аффинным расположением, встроенный в экран «Париж → Город сегодня», кнопка включения и прозрачность. Используется архивный JPEG той же LoC-карты и маска по выпуклой оболочке опорных точек.
- `eras/data/paris-1878-research-overlay.json`: точные копии **15 исходных GCP** и коэффициентов из `data/vision-lab/georef-paris-1878.json`. Все точки имеют статус **manual_GCP_review_required**. Мы НЕ объявляем их точность установленной.
- Переключатель аэрофотосъёмки французского IGN BD ORTHO через официальное WMTS `https://data.geopf.fr/wmts` с слоем `ORTHOIMAGERY.ORTHOPHOTOS`, TileMatrixSet `PM`. Лицензия французской государственной базы: [Licence Ouverte 2.0](https://www.data.gouv.fr/datasets/bd-ortho-r). Это **аэрофотосъёмка**, не «спутник OpenStreetMap»; отдельный год съёмки в районе конкретного памятника пока не установлен.
- На iPhone/iPad/десктопе UI проверяется `tests/browser/qa_eras.js`: переключение, геометрическая матрица, 15 маркеров, прозрачность, возврат к исходной карте.

**Расчёт:** коэффициенты аффинной модели задают приблизительную местопозицию пикселя старой карты, а Leaflet переводит современную географическую точку в текущую проекцию экрана. Для высоких приближений остаются остаточные ошибки и возможные локальные деформации скана. Показатель RMS ≈25,9 м означает внутреннюю ошибку модели; он **не** определяет, верно ли человек выбрал точку на скане.

## Шесть официальных аэрофотофрагментов IGN (дополнительный эксперимент)

Скрипт `tools/iiif/render_ign_ortho_review.py` делает не больше **6 отдельных WMS GetMap** запросов у IGN, каждый по собственным координатам памятника, с правильным BBOX в EPSG:3857, и формирует новую HTML-галерею рядом с ранее созданными фрагментами LoC:

```bash
python -m tools.iiif.render_paris_gcp_review \
  --historic-image eras/img/loc-2012586603-paris-1878.jpg \
  --out /tmp/paris-1878-gcp-review

python -m tools.iiif.render_ign_ortho_review \
  --source /tmp/paris-1878-gcp-review \
  --out /tmp/paris-1878-ign-review \
  --delay 1
```

В GitHub Actions опциональный шаг `Optional official IGN aerial comparison` может собрать артефакт `paris-1878-ign-aerial-review`. Если IGN откажет или сеть недоступна, отчёт **не** будет подменён тестовым изображением; основной CI работает без внешнего WMS. Год и геометрия аэрофотосъёмки требуют дополнительной проверки по метаданным, а точность исторических GCP — независимо.

Официальная спецификация WMS/WMTS: https://cartes.gouv.fr ; описание открытого набора BD ORTHO: https://www.data.gouv.fr/datasets/bd-ortho-r ; архивный план LoC: https://www.loc.gov/item/2012586603/ .
